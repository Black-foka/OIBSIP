# OIBSIP Cyber Security Task 1 — Basic Network Scanning with Nmap

## Objective

The objective of this task was to perform a basic network scan using Nmap to identify open ports and services running on a locally controlled machine, and to document the findings with a security analysis.

## Tools and Environment

- Nmap 7.94SVN
- Ubuntu 24.04.1 LTS
- WSL2
- Python 3.12.3
- Linux terminal

## What is Nmap?

Nmap (Network Mapper) is a network scanning and security auditing tool. It can be used to discover hosts and services on a network and gather information such as open ports, running services, service versions, and, where possible, operating-system information.

## Why Network Scanning Matters

Network scanning helps security professionals understand what systems and services are exposed on a network.

Identifying open ports and running services can help administrators detect unnecessary services, reduce attack surface, identify potential security risks, and improve the security configuration of systems.

## Methodology

The scan was performed against a locally controlled Ubuntu WSL2 environment.

The first basic scan showed that the target host was reachable, but all 1,000 TCP ports scanned by default were closed.

A controlled Python HTTP test server was then created on TCP port 8080. The server contained only a simple test page created for this exercise.

The following scans were performed:

### Basic Scan

```bash
nmap 172.17.154.248
```

### Service Version Scan

```bash
nmap -sV 172.17.154.248
```

### OS Detection Scan

```bash
sudo nmap -O 172.17.154.248
```

## Findings

The service-version scan identified the following open port:

| Port | State | Service | Version |
|------|-------|---------|---------|
| 8080/tcp | Open | HTTP | SimpleHTTPServer 0.6 (Python 3.12.3) |

The basic scan confirmed that the target host was reachable and that TCP port 8080 was open after the test HTTP server was started.

The OS detection scan returned:

```text
No exact OS matches for host
```

Nmap produced a Linux/x86_64 network fingerprint but did not identify an exact operating-system match. The target environment was independently identified as Ubuntu 24.04.1 LTS running under WSL2.

## Open Port and Service Analysis

### TCP Port 8080 — HTTP

**Service:** HTTP  
**Application:** SimpleHTTPServer 0.6  
**Python Version:** 3.12.3

Port 8080 was used by Python's built-in HTTP server to provide HTTP access to the local test directory created for this exercise.

An open network service increases the attack surface of a host. The Python test server is appropriate for a controlled development or testing environment, but it should not be treated as a production web server.

The server was deliberately bound to `0.0.0.0`, causing it to listen on available network interfaces rather than only localhost. In a real environment, unnecessary exposure could allow unauthorized clients to interact with the service or access files that should not be exposed.

For this exercise, the server contained only a test file and was running in a locally controlled environment.

## Service Detection Observations

During the service-version scan, the Python HTTP server recorded several requests generated by Nmap's service-detection probes.

Some requests returned HTTP 200 responses, while other probes resulted in responses such as `404 File Not Found` and `501 Unsupported Method`.

These observations demonstrate that service detection does more than simply check whether a port is open. Nmap sends probes to the service and examines the responses to help identify the application and version.

The connection-reset messages recorded by the Python server occurred during some of these probes and did not indicate that the system had been compromised.

## Security Risk Assessment

**Risk level in this controlled environment: Low**

The presence of an open HTTP port is not automatically a vulnerability. The primary concern is unnecessary exposure of a network service.

If a similar test server were exposed on a real system, potential security concerns could include unauthorized access to files being served, accidental disclosure of sensitive information, and an increased attack surface.

The test server was used only for this controlled exercise and was stopped after the scanning activities were completed.

## Ethical Use Guidelines

All Nmap scans performed for this project targeted a locally controlled Ubuntu WSL2 environment.

No external, production, or third-party systems were intentionally scanned.

Network scanning should only be performed against systems that you own or have explicit permission to test. Scanning systems without authorization can violate organizational policies, laws, or both.

## Conclusion

This exercise demonstrated the use of Nmap for basic network scanning, service-version detection, and OS detection in a controlled environment.

The basic scan identified the reachable host and the state of the scanned TCP ports. The service-version scan identified the HTTP service running on port 8080 as SimpleHTTPServer 0.6 on Python 3.12.3. The OS detection scan demonstrated that operating-system identification is not always exact, particularly in an environment such as WSL2.

The exercise also demonstrated the importance of identifying exposed services and considering their security implications. The HTTP test server was intentionally created for this exercise and was stopped after the scanning activities were completed.
