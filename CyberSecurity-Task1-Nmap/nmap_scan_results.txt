OASIS INFOBYTE — CYBER SECURITY TASK 1
Basic Network Scanning with Nmap
==================================================

1. ENVIRONMENT

Operating System: Ubuntu 24.04.1 LTS
Environment: WSL2
Architecture: x86_64
Nmap Version: 7.94SVN
Target IP: 172.17.154.248

2. NMAP INSTALLATION

I first checked whether Nmap was installed by running `nmap --version`.
The command returned a "command not found" message, indicating that
Nmap was not installed on the Ubuntu environment.

I then updated the Ubuntu package information and installed Nmap using
the following commands:

sudo apt update
sudo apt install nmap

After installation, I verified that Nmap was working by running:

nmap --version

The verification successfully returned Nmap version 7.94SVN.

Installation procedure:

1. Check whether Nmap is installed:
   nmap --version

2. Update the Ubuntu package information:
   sudo apt update

3. Install Nmap:
   sudo apt install nmap

4. Verify the installation:
   nmap --version

3. TARGET SETUP

The initial basic Nmap scan showed that the target host was reachable but
did not have any open TCP ports among the 1,000 ports scanned by default.

To provide a controlled service for the remaining parts of the exercise,
I created a local HTTP test server using Python's built-in HTTP server.
The server was created inside my own Ubuntu WSL2 environment and used
port 8080.

The test server contained only a simple HTML file created for this
exercise.

Target setup procedure:

1. Create the test-server directory:
   mkdir -p ~/OIBSIP/CyberSecurity-Task1-Nmap/test-server

2. Enter the directory:
   cd ~/OIBSIP/CyberSecurity-Task1-Nmap/test-server

3. Create a simple test page:
   echo "Oasis Infobyte Nmap Test Server" > index.html

4. Start the HTTP server on port 8080:
   python3 -m http.server 8080 --bind 0.0.0.0


4. BASIC NETWORK SCAN

The first basic scan was performed against the local target IP address.
The host was reachable, but Nmap reported that all 1,000 TCP ports
scanned were closed.

After the controlled HTTP test server was started, the basic scan was
performed again. This time, port 8080 was identified as open.

The scan confirmed that the target host was active and that the test
HTTP service was accessible on TCP port 8080.

Command used:

nmap 172.17.154.248

Initial result:

Host is up.
All 1000 scanned ports were in ignored states.
Not shown: 1000 closed tcp ports (conn-refused)

Result after starting the test server:

8080/tcp open


5. SERVICE VERSION SCAN

A service-version scan was performed using Nmap's -sV option. This scan
was used to identify the service and application version associated with
the open port.

Command used:

nmap -sV 172.17.154.248

Result:

PORT     STATE SERVICE VERSION
8080/tcp open  http    SimpleHTTPServer 0.6 (Python 3.12.3)

The scan identified TCP port 8080 as an open HTTP service and identified
the application as SimpleHTTPServer 0.6 running on Python 3.12.3.


6. OS DETECTION SCAN

An OS detection scan was performed using Nmap's -O option.

Command used:

sudo nmap -O 172.17.154.248

Result:

No exact OS matches for host

Nmap was unable to determine an exact operating-system match for the
target. The scan produced a Linux/x86_64 network fingerprint.

The target environment was independently identified as Ubuntu 24.04.1
LTS running under WSL2. This should not be presented as an operating
system detected by Nmap because Nmap did not produce an exact match.


7. OPEN PORT AND SERVICE ANALYSIS

Open Port: 8080/tcp
State: Open
Service: HTTP
Application: SimpleHTTPServer 0.6
Python Version: 3.12.3

Purpose of the service:

Port 8080 was used by the Python SimpleHTTPServer to provide HTTP access
to the local test directory created for this exercise.

Security considerations:

An open network service increases the attack surface of a host. The
Python test server is suitable for a controlled development or testing
environment but should not be considered a production web server.

The server was deliberately bound to 0.0.0.0, causing it to listen on
available network interfaces rather than only localhost. In a real
environment, unnecessary exposure of a service could allow unauthorized
clients to interact with it or access files that should not be exposed.

For this exercise, the server contained only a test file and was running
in a locally controlled environment.


8. OBSERVATIONS FROM SERVICE DETECTION

During the service-version scan, the Python HTTP server recorded several
requests generated by Nmap's service detection probes.

The server successfully returned HTTP 200 responses for some requests.
Other probes resulted in responses such as 404 File Not Found and
501 Unsupported Method.

These responses demonstrate that service detection does more than simply
check whether a port is open. Nmap sends probes to the service and
examines the responses to help identify the application and version.

The connection reset messages recorded by the Python server occurred
during some of these probes. They did not indicate that the system had
been compromised.


9. SECURITY RISK ASSESSMENT

Risk level in this controlled environment: Low.

The presence of an open HTTP port is not automatically a vulnerability.
The primary concern is unnecessary exposure of a network service.

If a similar test server were exposed on a real system, potential
security concerns could include unauthorized access to files being
served, accidental disclosure of sensitive information, and an
increased attack surface.

The test server was used only for this controlled exercise and was
stopped after the scanning activities were completed.


10. ETHICAL CONSIDERATIONS

All Nmap scans performed for this exercise targeted a locally controlled
Ubuntu WSL2 environment.

No external, production, or third-party systems were intentionally
scanned.

Network scanning should only be performed against systems that you own
or have explicit permission to test. Scanning systems without
authorization can violate organizational policies, laws, or both.


11. CONCLUSION

This exercise demonstrated the basic use of Nmap for network
reconnaissance in a controlled environment.

The basic scan identified whether the target was reachable and showed
the state of the scanned TCP ports. The service-version scan provided
additional information about the service running on port 8080. The OS
detection scan demonstrated that operating-system identification is not
always exact, particularly in environments such as WSL2.

The exercise also demonstrated the importance of documenting open
services and considering their security implications. The HTTP test
server was intentionally created for this exercise and was stopped after
the scans were completed.
